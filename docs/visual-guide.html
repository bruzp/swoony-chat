The app

How the chat app works

A visitor goes from landing page to private chat in a few taps. Nothing is saved for users; a small set of encrypted records is kept only because Philippine law (RA 11930) requires it.

Enter

Nickname, gender, age, country (pre-filled), optional bio, 18+ tick. Turnstile checks for bots once. A short "Before you start" rules popup follows.

Online list

Live list of everyone online, your country first. Filter by gender, age, country.

Open a chat

Tap a person. Each pair gets its own private chat room.

Talk

Text and emoji (1–3 emoji alone show big). A live typing bubble and "Seen". Links, contact details and rude words are blocked before sending.

End

Leave or block, and the other side sees "X left". Text is wiped 10 min later.

Staying safe automatically

Messages 5 per 5 s per chat, 1,000 chars
New chats 10 per minute
Same text to many 5+ people / min = spam (10+ chars)
Strikes 3 in 10 min = kicked
Kicks 3 in 24 h = ban

Reports and bans

No human review. A report counts only if you chatted and they sent at least one message. 3 counted reports in 24 h from 3 different devices and networks bans the device: 1 h, then 24 h, then 7 days. Reporting also blocks and saves an encrypted copy of that chat for 1 year.

Reconnects and tabs

One person per device: every tab shares the same identity. A phone lock or reload keeps you for 60 s and replays missed messages. 30 min of no activity logs you out.

What is kept, and for how long

Connection and chat records (who, with whom, when, IP, nickname): 6 months. Messages of all chats: 1 year, as compressed bundles in R2. All encrypted, readable only through the owner's admin page.

Owner only

Admin page at /s-admin

The owner has 24 hours to act on a takedown notice (RA 11930). The admin page replaces slow terminal commands: look up, ban, take down, hold, download case files. Only the owner's email, from the owner's IPs, gets in through Cloudflare Access.

Case lookup

Find records

Search by nickname or user ID and dates. Every search needs a case reference. Row actions ask for confirmation, repeating target and case.

Holds

Preserve evidence

Holds can only be extended, never released early (D8). Held rows are skipped by the clean-up.

Activity log

Tamper-evident

Every search, action and export is logged, each row hashing the one before. The page shows "chain intact" or where it breaks. Kept 1 year.

Downloads

CSV zip and PDF case file

The server builds the files. The PDF has a records fingerprint; the file's own hash is logged and shown after download. A chat over 4,000 messages downloads in parts.

System health

✓ Site · DB · Ban store · Lobby

Response times, online count, last 14 clean-up runs. Emails the owner if clean-up fails or skips 26 h.

Maintenance

Pause the site

Removes everyone at once and shows "Swoony is down for a short update." Admin, health and clean-up keep working.

Going live

Deployment steps

The first time, follow every step in order. Deploy only from main, and only after NPC registration. Steps marked dashboard are clicks in Cloudflare; terminal are commands.

  1. Accounts and domain dashboard

    Cloudflare account on Workers Paid (about $5/month). Buy swoony.chat. Turn on billing alerts. 

    npx wrangler login

  2. Database and ban store terminal

    Paste the printed ids into wrangler.jsonc, then create the tables. Re-run migrations whenever migrations/ gets a new file. 

    npx wrangler d1 create swoony
npx wrangler kv namespace create BANS
npx wrangler r2 bucket create swoony-archive
npx wrangler d1 migrations apply swoony --remote

  3. Admin sign-in (Cloudflare Access) dashboard

    Zero Trust org, One-time PIN on. App "Swoony admin" for /s-admin* and /api/s-admin/*, 8 h sessions. Allow your email, require your IPs. Copy the AUD tag.

  4. Alert emails dashboard

    Email Routing on, verify your inbox, create abuse@swoony.chat. Alerts send from alerts@swoony.chat.

  5. Turnstile and analytics dashboard

    Managed Turnstile widget and a Web Analytics site. Put both in .env.production (never commit it).

  6. Secrets terminal

    All 10 are required; deploy refuses without them. Keep RETENTION_KEY offline: lose it and the legal records can't be read. 

    npx wrangler secret put COOKIE_SECRETS
# also: IDENTITY_HASH_SECRET, TURNSTILE_SECRET, RETENTION_KEY,
# ADMIN_TOKEN, ACCESS_TEAM_DOMAIN, ACCESS_AUD, ADMIN_EMAILS,
# ALERT_EMAIL_FROM, ALERT_EMAIL_TO

  7. Load test terminal

    Pass: p95 round trip under 500 ms, errors under 1%. Last local run, 1,000 users: p95 127 ms, 0 errors. Where the real run happens is still open item 14. 

    node scripts/loadtest.ts --users 1000

  8. First deploy terminal dashboard

    Then attach the custom domain, and add the edge rate limit rule "API flood": /api/*, 100 requests per 10 s per IP, block 10 s. 

    git checkout main
npm run check
npm run deploy

  9. Check it works

    Chat between two phones. /s-admin in a private window shows the email-code page; System health is all green. /api/health returns {"status":"ok"}.

  10. Monitoring dashboard

    UptimeRobot on /api/health every 5 min. Cloudflare error and usage alerts. npx wrangler tail must never show message text, nicknames or IPs.

Every later deploy

  1. Merge into main only after review.
  2. New migration file? Run npx wrangler d1 migrations apply swoony --remote first.
  3. npm run check, then npm run deploy. No downtime needed.
  4. Broken? npx wrangler rollback (code only; fix database changes forward).
